Regular Expression Denial of Service (ReDoS)

How one innocent-looking regex can pin a CPU at 100% with a single short string.

1. What is it?

Most regex engines (including JavaScript's) use backtracking: when a pattern fails to match, the engine goes back and tries the other ways it could have matched. For well-written patterns that is cheap. For patterns with nested or overlapping quantifiers, such as (a+)+, the number of alternatives explodes exponentially with the input length.

A ReDoS attack sends an input that almost matches, forcing the engine to try every alternative before it gives up.

Real-world impact. JavaScript runs on a single thread, so a stuck regex freezes the whole page or blocks a whole Node.js server. Regex backtracking was behind a global Cloudflare outage in 2019 and a Stack Overflow outage in 2016. One request can take a service down, which makes it cheap for an attacker and expensive for the victim.

2. How it works

  1. The app validates usernames with /^([a-z0-9]+)+$/i. For normal input it is instant.
  2. The attacker sends many valid characters followed by one invalid one: aaaa...aaaa!
  3. The trailing ! makes the match fail, so the engine backtracks and tries every way of splitting the as between the inner + and the outer +.
  4. Each extra character roughly doubles the work. 25 characters takes milliseconds, 35 takes minutes.

3. How to fix it

Why it works.

  • [a-z0-9]+ has a single quantifier, so there is only one way to match each character. The engine makes one pass and the cost grows linearly (O(n)).
  • The length limit rejects oversized input before any regex runs, which caps the worst case even if another pattern is imperfect.
  • Defence in depth: avoid nested quantifiers and overlapping alternations, prefer linear-time engines such as RE2 for untrusted input, and run risky matching with a timeout or in a worker.
