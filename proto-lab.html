LAB 3 · HANDS-ON

Prototype Pollution: Settings Page

Your goal Unlock the admin panel. The app removes a top-level isAdmin key from your input, so you must get config.isAdmin to become true some other way. Settings can come from the box below or from the page URL (?query or #hash).

Hints

Hint 1: Where is the gadget?

The page runs if (config.isAdmin), but config is never given an isAdmin of its own. Where else could a value come from? Think about the prototype chain.

Hint 2: Reach the prototype

The merge function copies nested objects recursively. Which special key, when merged into any object, points to Object.prototype? Use bracket notation in a query string, such as a[b]=1, or nested objects in JSON.

Hint 3: Check the live view

The Object.prototype state panel shows any property that was added after the page loaded. If the key shows up there, you have polluted the prototype.

Show solution

With the switch OFF, submit any one of these in the box:

?__proto__[isAdmin]=true
{"__proto__": {"isAdmin": true}}
{"constructor": {"prototype": {"isAdmin": true}}}

Or put it in the address bar: proto-lab.html?__proto__[isAdmin]=true (or #__proto__[isAdmin]=true). The merge writes isAdmin onto Object.prototype, so config.isAdmin is inherited and the gadget opens the panel.

Sending {"isAdmin": true} directly does not work: the app strips it. Turn the switch ON and repeat the payload: the forbidden key is skipped and nothing is polluted.

Fix the vulnerability

OFF runs the vulnerable code. ON runs the patched code. Exploit, flip, then retry.
