LAB 1 · HANDS-ON

ReDoS: Username Validator

Your goal Make the username validator run for more than 2 seconds with a single input. The regex runs in a sandboxed Web Worker, so your tab will never freeze.

Hints

Hint 1: What is the validator doing?

Open the Active code panel below. The pattern has a quantifier inside a group that is itself quantified: ([a-z0-9]+)+. That is the shape that causes catastrophic backtracking.

Hint 2: What input hurts it most?

You need a string that is almost valid: many allowed characters, then one character that makes the match fail at the very end. The Safe sample button fills in a normal username so you can see a fast run. The Attack sample button fills in a long near-miss string. Both buttons only fill the box: you still press Test yourself.

Hint 3: How long should it be?

Each extra character roughly doubles the time. Around 30 characters is already several seconds. Watch the live timer: the lab is solved once it passes 2000 ms.

Show solution

With the switch OFF, enter 35 letter a characters followed by !:

aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa!

Press Test. The regex cannot match because of the final !, so it tries every way to split the as between the two + operators. After 2 seconds the worker is terminated and the lab is marked solved. On a very fast machine, add more a characters.

Now turn the switch ON and test the same string: it is rejected instantly.

Fix the vulnerability

OFF runs the vulnerable code. ON runs the patched code. Exploit, flip, then retry.
